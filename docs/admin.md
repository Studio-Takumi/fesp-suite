# 管理者サイト仕様

## 全体レイアウト

`app/(dashboard)/` にルートグループを切り、その `layout.tsx` で左サイドメニュー＋本文エリアの枠を作る（URLは変わらない）。
ログイン（`/login`）・新規登録（`/signup`）はこのグループの外に置くので、サイドメニューは出ない。
`/articles`（記事一覧）とその配下もメニューには出さない。

PC（1440×900）前提。スマホ・タブレット幅への対応はしない。

### ログインの確認

- ログイン・新規登録以外のページは、ログインしていないと使えない。未ログインで開くと `/login?redirect=<開こうとしたパス>` に移動する
- ログインしているかを確かめ終わるまでは、サイドメニューも本文も出さない
- ログイン状態は常に保持する（ブラウザを閉じても残る）

### サイドメニュー

- 項目の定義は配列1か所にまとめてあり、ページが増えたらそこに足すだけでよい
- いま開いているページの項目をハイライトする（背景 `sky-100` + アイコン・文字を `sky-500` で太字化）
- 未実装ページの項目は無効表示（クリック不可・グレーアウト）にし、「準備中」バッジを付ける。404には飛ばさない
- 項目は2階層。下位項目は親の項目の下に字下げして出す。親が準備中でも下位項目は開ける
- 開閉できる。閉じるとアイコンだけの細い表示になる。開閉状態は Zustand（`stores/ui.ts` の `isSidebarOpen`）に持ち、永続化しない（リロードで開いた状態に戻る）
- 一番下のユーザー欄に、ログイン中のユーザーのメールアドレスとログアウトボタンを出す（名前・役割は出さない）
    - アイコンの丸にはメールアドレスの先頭1文字を大文字で出す
    - 閉じているときはログアウトボタンだけを出す
    - ログアウトボタンでログアウトし、`/login` に移動する。読み込み済みのデータは残さない

## ページ

### ログイン（`/login`）

- 「Google でログイン」ボタンと、メールアドレス・パスワードの入力欄を置く
- 「Google でログイン」を押すと Google の画面に移動し、戻ってきたらログインした状態になる。初めての Google アカウントなら、その時点でアカウントができる
- 「ログイン」を押したときに、メールアドレスの形式とパスワードが8文字以上かを確かめ、合わなければ入力欄の下にエラーを出す
    - 送信中はボタンを無効にする
    - メールアドレスかパスワードが違うときは「メールアドレスまたはパスワードが違います」、それ以外の失敗は「時間をおいて再度お試しください」と出す
- パスワードの入力欄の目のアイコンで、パスワードの表示・非表示を切り替える
- ログインできたら `redirect` のパスに移動する。`redirect` がない、または `/` で始まるサイト内のパスでない（`//` で始まるものを含む）ときは `/` に移動する
- ログイン済みで開いたときも、同じ規則ですぐに移動する
- 「新規登録」のリンクで `/signup` に移動する。`redirect` は引き継ぐ

### 新規登録（`/signup`）

- 入力欄・入力の確かめ方・移動先の規則はログインと同じ。ボタンは「Google で登録」「登録する」
- パスワードの入力欄の下に「8文字以上で入力してください」と出す
- 「登録する」でアカウントを作り、そのままログインした状態で `redirect` のパスに移動する（メール確認はしない）
- 登録済みのメールアドレスのときは「このメールアドレスは登録済みです」と出す
- 「ログイン」のリンクで `/login` に移動する。`redirect` は引き継ぐ

### ダッシュボード（`/`）

見出しだけの空ページ。中身は未着手。

### 記事一覧（`/articles`）

- 対象のイベントは env の `NEXT_PUBLIC_EVENT_ID` で固定する
- そのイベントの記事を、更新日時の新しい順に先頭100件まで読み込む。並べ替え・絞り込み・ページ送りは、読み込んだ100件の中で行う
- 各行にタイトル・公開状態・更新日時（`YYYY/MM/DD HH:mm`）を出し、タイトルのクリックで `/articles/[id]` へ移動する
- タイトルが空の記事は「（無題）」と出す
- 公開状態は、下書き（`draft`）なら「下書き」、公開（`published`）なら「公開中」と出す。予約（`schedule`）があれば、下書きは「予約中」、公開中は「公開中（更新予約あり）」とバッジで出す
    - バッジの色は、下書きはグレー、予約中は黄、公開中（更新予約あり）は水色、公開中は緑
- 0件のときは、表の代わりに「記事がありません」と出す
- 「新規作成」ボタンでタイトル・本文とも空の記事を下書きで作り（`POST /api/articles`）、作った記事の `/articles/[id]` へ移動する
- 並べ替え・絞り込み・ページの状態は画面の中だけで持ち、一覧を開き直すと初期状態に戻る

#### 並べ替え

- タイトル・公開状態・更新日時の列見出しをクリックすると、その列で並べ替える。もう一度クリックすると昇順・降順が入れ替わる（並べ替えなしには戻らない）
- 初めは更新日時の新しい順に並べる。更新日時は最初のクリックで新しい順、タイトル・公開状態は昇順になる
- 公開状態の昇順は、下書き → 予約中 → 公開中（更新予約あり）→ 公開中

#### 絞り込み

- 表の上に、タイトルの検索欄と公開状態のセレクトを置く。両方を同時に使える
    - 検索欄は、入力した文字をタイトルに含む記事に絞り込む（大文字・小文字は区別しない）。空のタイトルは「（無題）」では引っかからない
    - セレクトは「すべて」「下書き」「予約中」「公開中」「公開中（更新予約あり）」から選ぶ。初めは「すべて」
- 絞り込みを変えたら1ページ目に戻る
- 絞り込んで0件になったら、表の中に「条件に合う記事がありません」と出す

#### ページ送り

- 1ページに50件まで出す
- 表の下に「全n件中 x〜y件」（n は絞り込んだあとの件数。0件なら「全0件」）と「前へ」「次へ」ボタン（左右の矢印のアイコンだけ）を出す。最初のページでは「前へ」、最後のページでは「次へ」を押せない

### 記事エディタ（`/articles/[id]`）

BlockNote（[`docs/article-system.md`](./article-system.md)）でテキスト・見出し・リスト・
チェックリスト・トグルリスト・引用・注意書き・区切り線・表と、独自コンポーネントのブロックを編集する画面。

- 開いたときに `GET /api/articles/:id` で記事を読み込み、最新の版（`latest_history`）のタイトル・本文をタイトルの入力欄とエディタの初期値にする。最新の版が無ければ記事のタイトル・本文を使う
- 記事が見つからない（404）ときは、エディタの代わりに「記事が見つかりません」と一覧へのリンクを出す
- 見出し（「記事エディタ」）の下に「作成者: <表示名>」と出す。表示名が未設定なら「作成者: （名前未設定）」
- 公開中の記事で、最新の版が公開中の版（`published_version`）と違う（一時保存した変更がある）ときは、作成者の下に「公開していない変更があります」と出す
- 予約（`schedule`）があるときは、その下に「YYYY/MM/DD HH:mm に公開予定」（日本時間）と出す
    - 最新の版が予約した版と違うときは、「予約した版のあとに保存した変更があります（予約には入りません）」とも出す
- タイトル・公開日時・本文の入力欄には、それぞれ上にラベル（「タイトル」「公開日時」「本文」）を出す
- 本文の上にタイトルの入力欄を置く（100文字まで。空でもよい）
- タイトルの下に公開日時の欄を置く。日付を選ぶボタン（押すとカレンダーを出す）と時刻の入力欄を横に並べる
    - 日付のボタンには選んだ日付を `YYYY/MM/DD` で出す。選んでいなければ「日付を選ぶ」と出す
    - カレンダーは日本語で出す（曜日は「日」〜「土」、見出しは `YYYY年M月`）
    - 予約があれば予約の日付・時刻を、無ければ両方とも空を初期値にする。選んだ日時は日本時間として扱う
    - 日付か時刻が入っているときは、横に「日時をクリア」ボタンを出す。押すと日付・時刻を両方とも空にする
      （カレンダーで選んでいる日をもう一度押しても、日付の選択は外れる）
- 「保存」ボタンの左に「公開」のスイッチを置き、記事の公開状態を初期値にする（オンで公開、オフで下書き）
    - 公開日時（日付・時刻のどちらか）が入っている間は、スイッチを無効にする。今すぐ公開するには日時を空にする
- 「保存」ボタンを押したときだけ、タイトル・本文・公開状態・公開日時をまとめて保存する。自動保存はしない。スイッチを切り替えただけ・日時を変えただけでは保存しない
    - 公開日時が入っているときは、タイトル・本文を保存し（`PUT /api/articles/:id`）、保存した最新の版（`latest_history` の `version` / `updated_at`）をその日時に公開する予約にする（`PUT /api/articles/:id/schedule`）
    - 公開日時が空で、記事に予約があるときは、保存してから予約を取り消す（`DELETE /api/articles/:id/schedule`）
    - 日付か時刻の片方だけが入っているときは「日付と時刻の両方を指定してください」、日時が現在以前のときは「現在より後の日時を指定してください」を欄の下に出して保存しない
    - 公開中の記事で、スイッチがオンのまま「保存」を押したときは、ダイアログ「公開中の記事です」（本文「一時保存すると、公開中の記事はそのままで変更だけを保存します。」）を出す
        - 公開日時が入っているときは、本文に「YYYY/MM/DD HH:mm に公開へ反映されます。」も出す
        - 「一時保存する」: 公開中の記事は変えずに、タイトル・本文を保存する（`status` を送らない）。公開日時が入っていれば、その日時の予約にする
        - 「公開に反映する」: タイトル・本文を保存し、公開中の記事に反映する（`status` を `published` で送る）。予約があれば消え、公開日時の欄も空になる
        - 「キャンセル」: 保存しない
    - それ以外（下書きの記事、スイッチをオフにして保存）は、ダイアログを出さずにスイッチの状態で保存する
    - 公開中かどうかは、読み込んだ（保存したあとは保存の結果の）記事の公開状態で決める
    - タイトルが100文字を超えていたら、入力欄の下にエラーを出して保存しない
    - 保存中はボタンを無効にする
    - 成功したら「保存しました」（予約したときは「保存して予約しました」、予約を取り消したときは「保存して予約を取り消しました」）、失敗したらエラーメッセージを出す
    - これらの表示は、タイトル・本文・公開日時を編集するか、スイッチを切り替えると消す
- 本文のJSONを確認用の折りたたみで出す

#### 注意書き（`callout`）

読み飛ばされたくない文章を色付きの枠で囲むブロック。見出し・引用と同じテキスト系のブロックで、サイドパネルは出さない。

- スラッシュメニューの「基本ブロック」グループ（見出し・引用などと同じグループ）の「注意書き」から挿入する。挿入した直後の種類は「注意」（`caution`）
- 枠の中に、見出しの行と本文を出す
    - 見出しの行は、種類のアイコンと表示名（「情報」「注意」「警告」）。見出しは編集できない
    - 本文は、見出しの行の下で文字を直接編集する
    - Tab で入れた子ブロック（箇条書きなど）も、枠の中に出す
- 見出しの行のアイコンを押すとメニューが開き、「情報」「注意」「警告」から種類を選べる。選ぶと種類（`variant`）が変わり、枠の色・アイコン・見出しも変わる
    - メニューでは、いまの種類にチェックを付ける
    - 種類を変えるのは本文の変更と同じ扱いで、保存は「保存」ボタンで行う
- 枠の色は、ウェブアプリと同じく種類ごとに緑（情報）・琥珀（注意）・赤（警告）にする

##### ページ見出し（`pageHeader`）

- 挿入した直後は、英語ラベル・日本語タイトルとも空

### 開催日（`/schedule/event-days`）

模擬店・出演者・スケジュールが参照する開催日（Day1 / Day2）の一覧と編集。

- 対象のイベントは env の `NEXT_PUBLIC_EVENT_ID` で固定する
- そのイベントの開催日を `day` の順に表で出す（`GET /api/event-days`）
- 列は「何日目」「日付」「表示名」。何日目は「<n>日目」と出し、編集させない
- 日付・表示名は表の中で直接編集する。入力欄から離れたときに値が変わっていれば、その時点で保存する（`PUT /api/event-days/:id`）。「変更を保存」ボタンは置かない
    - 表示名は空でよい。空にすると `null` で保存し、ウェブアプリでは「<n>日目」と出る
    - 日付を空にしたときは保存せず、元の値に戻す
- 表の下の入力欄（日付・表示名）と「追加」ボタンで足す（`POST /api/event-days`）。`day` はいまの最大 + 1（1件も無ければ 1）にする
    - 日付が空の間は「追加」ボタンを押せない
- 行の「削除」ボタンで消す（`DELETE /api/event-days/:id`）。確認のダイアログは出さない
    - 消したら、後ろの行の `day` を1つずつ前へ詰める（`day` がイベントごとに1から続くようにするため）
- 並べ替えのドラッグ&ドロップは置かない。並び順は `day` そのもので、追加した順に増える
- 読み込み中は「読み込み中…」、0件のときは表の代わりに「開催日がありません」と出す
- 追加・保存・削除に失敗したら、表の上にエラーメッセージを出す
    - 同じ日付（または同じ `day`）の開催日がすでにあるとき（`409`）は「同じ日付の開催日がすでにあります」
    - 参照されていて消せないとき（`409`）は「模擬店・出演者・スケジュールで使われているため削除できません」

### 場所（`/map/places`）

模擬店・出演者が参照する場所（会場・教室）の一覧と編集。

- 対象のイベントは開催日と同じく env で固定する
- そのイベントの場所を `sort_order` の順に表で出す（`GET /api/places`）
- 列は並べ替えのつまみと「場所名」「建物」「階」
- 場所名・建物・階は表の中で直接編集し、入力欄から離れた時点で保存する（`PUT /api/places/:id`）
    - 建物・階は空でよい。空にすると `null` で保存する
    - 場所名を空にしたときは保存せず、元の値に戻す
- 表の下の入力欄と「追加」ボタンで足す（`POST /api/places`）。`sort_order` はいまの最大 + 1（1件も無ければ 0）にする
    - 場所名が空の間は「追加」ボタンを押せない
- つまみをドラッグして行を入れ替える。離した時点で、上から順に `sort_order` を 0 から振り直して保存する（値が変わる行だけ `PUT` する）
- 行の「削除」ボタンで消す（`DELETE /api/places/:id`）。確認のダイアログは出さない
- 読み込み中・0件・エラーの出し方は開催日と同じ（0件は「場所がありません」）
    - 参照されていて消せないとき（`409`）は「模擬店・出演者で使われているため削除できません」

### タグ（`/news/tags`）

お知らせ・ブログ・模擬店・出演者で共通に使うタグの一覧と編集。種類ごとには分けない。

- 対象のイベントは開催日と同じく env で固定する
- そのイベントのタグを `sort_order` の順に表で出す（`GET /api/tags`）
- 列は並べ替えのつまみと「タグ名」。編集・追加・削除・並べ替えの操作は場所と同じ
- タグは記事に付いていても消せる（付いていたぶんは一緒に外れる）ので、削除で `409` にはならない
- 同じ名前のタグがすでにあるとき（`409`）は「同じ名前のタグがすでにあります」と出す
- 0件のときは「タグがありません」と出す
