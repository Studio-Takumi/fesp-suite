# 113 docs: #113 デザインを DB / API の設計に合わせる

## やったこと

#105（DB設計）・#111（API設計）で決めた形と食い違っていた管理者サイトの3画面を、
`docs/design/ui-design.pen` 上で直した。あわせて iPhone の画面に重ねていた注釈の枠を外し、
`docs/db.md` の記述が決めたことと逆になっていたところを直した。コードは触っていない。

## 実装メモ

- **管理者サイトの個別編集ページは記事エディタを持つ、という決まりにした。** ブロックの props で
  表せない設定（団体名・開催日・場所・カテゴリ・メニュー・注意事項・タグ）は、今までどおり専用の欄で編集する。
  模擬店編集は「紹介文（`shops.description`）」と「本文（`articles`）」の2つを持つ形になった

- **「出演」は表示側からも消した。** 設定パネルの入力だけ消すと、枠やモーダルに出ている
  「軽音楽部 ほか5組」「各クラス」のようなデータの出どころが無くなる。これらは団体名の自由入力で、
  `schedule_events.artist_id` では表せないため、表示ごと落とした。出演者との紐付けは
  「『詳しく見る』のリンク先」に一本化する

- **`admin / 模擬店編集` だけフレームの高さを 900 → 1240 にした**（理由: 本文の記事エディタを足すと
  メニューがフレームの外に出てレビューできなくなる。下に他のアートボードが無いので干渉しない）。
  他の管理者サイトの画面は 1440x900 のまま

- **天気の「雨雲レーダー」は、トグルごと消えた。** 対応する独自コンポーネントが無く、機能自体も
  まだ作らないものなので、この版では落としている

- **注釈は枠だけ外し、ラベルと凡例は残した**（理由: ラベルは画面の外（右隣）に置いてあって画面を覆っていない。
  枠を外しても、ラベルの位置と色でどのブロックかは読める。凡例はラベルの色にもかかっているので生きている）

- **`docs/db.md` は「決めたことと逆に書いてあるところ」だけ直した。** `shops` の注意事項を
  「列に持たず `callout` で書く」から「`notes` の列で持つ」に変えている。
  `shop_categories` や `event_days` の表示時間のように**足りない**ぶんは、実装する Issue の
  ステップ5で書くので、ここでは触っていない

## 詰まった点

- **pen.dev の編集がファイルに書き出されるまで、コミットできなかった。** MCP の `execute` で加えた変更は
  アプリの中には即座に入るが、`.pen` のファイル自体は保存するまで更新されない。
  ファイルの更新を待ってからコミットした
