## やったこと

`docs/design/ui-design.pen` に、ウェブアプリ（来場者向け）と管理者サイトの画面を39アートボード分作成した。

## 実装メモ

### 前バージョンの反省から入れたもの

[高校の文化祭でウェブアプリを作った話](https://qiita.com/pimach/items/0562c4eef06ceb91b1db) を読んで、
UIに関する反省を3点取り込んだ。

- **日付の表示を大きく**（理由: 「日にちの部分の表示をでかくしてくれという意見が多かった」）。
  Schedule・Shop・Artist の日付タブを `Day1 / 6/6 (土)` の大きいピルにし、カードの Dayバッジも太字にした
- **注意書きを目立たせる**（理由: 「どーせ見ないよなーとか思いつつあんま目立たないデザインにしてた」→
  実際に読まれず、購入制限を知らない人が出た）。模擬店の注意事項をグレーの箱から琥珀色の警告ボックス + ⚠️ に変更
- **並び替え・絞り込みを最初から入れる**（理由: 前回は時間切れで断念）。Shop・Artist の一覧に
  日付タブ → 検索 + 並び替え → タグタブ の3段を置いた

同記事の「アプリのインストールに抵抗を持つ人がいる」を受けてウェブアプリ前提とし、
端末のステータスバー（電波・電池）はアートボードから外している。

### 画面設計の判断

- **iPad もボトムナビ**にした（理由: iPhone と操作を揃える。サイドレールだと両手持ち前提になる）
- **一覧 + 個別があるページは iPad で2ペイン**（News / Blog / Shop / Artist）。
  左が一覧・右が個別で、選択行は `sky-50`。Home / Schedule / Map / Weather は1カラムのまま横に伸ばす
- **Map は Google Maps 寄せ**。iPhone は引き上げ式のボトムシート、iPad は左に浮かぶパネル。
  ピンをタップしたときに別モーダルを出さず、シート側で情報を出す
- **Schedule のモーダルは中央ダイアログ**。サムネイル + 時間・会場・出演 + 「詳しく見る」
- **個別ページのアプリバーは画像の上に重ねる**。アイコンは半透明の黒丸（`#0F172A` 40%）+ 白アイコン。
  絶対配置にしただけだと画像の下に隠れるので、子の並び順を画像より後ろにしている
- **News と Blog のサマリーは共通**。タイトル → アバター + 投稿者 + 日時 → ハッシュタグ の順で、
  iPhone / iPad の4画面すべて同じ部品
- **ハッシュタグに背景色は付けない**（理由: 単一選択のチップに見えてしまうため。複数付く前提）
- **権限設定は役割ではなく権限ごとの列**（理由: 管理したい権限は増えていくので、
  役割を4段階に固定すると足りなくなる）。いまは6列。10列を超えたら横スクロールになるので、
  そのときはグループ化か詳細パネルへの分離を検討する

### 見送ったもの

- **ダークテーマのアートボード**（理由: 枚数が倍になり散らかる。色はすべて変数化してあるので、
  pen.dev の theme で後から足せる）
- **ローディング・オフラインのアートボード**（理由: 空状態から想像がつく。
  オフラインの帯だけ `OfflineBar` として共通パーツに残した）
- **アンケート画面**（理由: Googleフォームの埋め込みのみで、独自UIを持たないため）
- **リアルタイム・運営系の画面**（理由: 情報発信系を先に固める方針。
  管理画面には「準備中」のトグルだけ置いた）

### その他

- 画像は Unsplash のプレースホルダ（青空・花・フルーツ）。サムネイルは16:9、商品写真は正方形
- iPad の記事ヘッダー画像だけ 5:2（834×300）にしている。理由: 834px幅で16:9だと高さ469pxになり、
  834pxの画面をほとんど埋めてしまうため

## 詰まった点

- **pen.dev の linear gradient の向き**が直感と逆だった。`rotation: 0` のとき `position: 0` が
  下端になる。一度あからさまな色（赤→緑）を当てて向きを確認してから本来の色にした
- **絶対配置は重なり順を変えない**。`layoutPosition: "absolute"` にしても子の並び順で描画順が決まるので、
  画像に重ねる要素は画像より後ろのインデックスに移す必要がある
- **コンポーネントのインスタンスに渡した上書き内容（`descendants`）は、テキストノードの一括置換では拾えない**。
  文言を差し替えるときは ref ノードの `descendants` も別途なめる必要があった
